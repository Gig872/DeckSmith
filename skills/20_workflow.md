# 20 建卡工作流（收敛路径，按序执行）

1. **解析需求**：识别需要哪些部件与参数。**缺关键参数就用 `ask_user` 提问**（讲含义 + 给建议范围），
   确认后 `remember_requirement` 落账；建卡前 `list_requirements` 核对，不臆造。
2. **定物理意图**：`set_model_intent`（场景/驱动/能量/预判范围）——见 skill 15。
   **写不出自洽的意图就先别建卡**（尤其核对边界条件是否自洽、质量/能量能否平衡）。
3. **查格式**：先 `lookup_doc(部件类型)`、`read_example(相近参考)`，照规范写（禁止凭记忆编卡片）。
4. **落盘**：`write_file` 写 `.i`（可先写一版草稿）。
5. **静态校验**：`validate_i`。
6. **真跑**：`run_relap5`，再用 `parse_output` 看结果。
7. **排错循环**：若报错 → `parse_output` 取出错误行 → 定位到具体卡 → 改（`edit_file`/`write_file`）→ 重跑；
   直到"**正常结束 + 0 错误**"。同类改动不要反复空转（连续两次相同即换思路）。
   - **终止判据**：一旦 `parse_output` 报出「正常结束=True 且错误数=0」，立即进入第 8 步，**不要再**去 `.o` 里反复找表/翻数值。
8. **物理校验 + 自主评估（必须，不通过不得交付）**：
   - `check_sanity(o_path)`（压力/温度极值 + 质量守恒误差）+ `result_summary(o_path)`（重复连接、节点净流量）
     → 守恒/拓扑体检；
   - **`verify_result(o_path, power?, mdot?, tin?)`（自主评估）** → 饱和一致性 + 能量平衡量级核对；
   - 与第 2 步的**预判范围**逐项比对；**不一致就回头改设计**，不许圆谎。
   结论按 **通过 / 存疑 / 未覆盖** 三档如实给，**存疑必须明说**。见 **skill 70**。
9. **交付**：用自然语言讲清**物理故事**（谁驱动、能量如何平衡、为什么结果合理）+ 模型结构与关键参数；
   若是**瞬态/趋势**类结果，用 `plot_series` 出图并**对着曲线讲**（先拿特征再讲机理，见 skill 60）；
   若任务要求沉淀，则 `save_example` 存入自主学习库。
   - **入库前再校一遍**：对**将要保存的整段文本**（含你加的说明头）跑 `validate_i`。
     **说明的每一行都要以 `*`（或标题 `=`）开头**——否则 RELAP5 会把说明行当卡读，
     存进库的样例就废了（实测踩过）。
   - **禁止空转**：看运行结果**只用 `parse_output` / `check_sanity` / `result_summary` / `verify_result`**。
     不要用 `python_exec`/`run_command` 反复在 `.o` 里 `find`/搜表——输出表名与列序随工况变化，
     **极易读错列**（例如把声速列当成温度）。

## 工具选择速查
- 查资料：`lookup_doc`（本地手册，权威）、`read_example`、`glossary`；缺信息：`ask_user`；
  联网（手册不够时）：`web_search`（看摘要）→ **`web_fetch`（抓正文深读）**，查询用简短关键词
- 会话/教学：`set_user_level`、`remember_requirement`、`list_requirements`、`set_model_intent`
- 写卡：`write_file`、`edit_file`、`read_file`；列目录：`list_files`
- 验证：`validate_i` → `run_relap5` → `parse_output` → **`check_sanity`（物理）** → `result_summary`（末态读数）
- **瞬态**：`transient_history(o, what)` 取**时间历程**——`what="flow"`（各接管流量）、
  `what="volume"`（逐控制体温度）、`what="state"`（压力/温度极值）；核对"随时间怎么变"**只用它**，
  **不要**用 `python_exec` 手抠 `.o`
- 沉淀：`save_example`、`remember`
- 批量/参数化仿真：`set_batch_plan`（先谈框架）、`batch_sim`（自动生成+真跑+汇总）——见 **skill 50**
- **用图讲结果**：`plot_series`（出图+曲线特征，界面自动弹窗）、`curve_features`（只要特征）、
  `scan_series`（批量趋势）——见 **skill 60**（先把数拿到手，再讲物理）
- **自主评估**：`verify_result`（饱和一致性 + 能量平衡）——见 **skill 70**（下结论前必做，存疑必明说）

## 三个样例库（按权威降序，务必分清）
- **`human` 人工基座**：人工给的**可信种子**，**最高权重**，**只读**（禁止写入）。冲突时以它为准。
- **`agent` 可信基座**：agent 生成、**已核验**的可跑样例（冻结归档，不可同名覆盖）。
  当用户明确要求"构建/扩充参考库"时，用 `save_example(..., lib="agent")` 把你**已真跑验证**的
  新样例存档到这里。
- **`learned` 工作成果**：**你自己的成果**——学到的、总结的、改进的默认存这里（`save_example` 默认）。
- `list/read/find_example` 三档都会看，并标注来源；**权威 human > agent > learned**，
  同等相关时优先用更高权威档。
- 遇到**新部件类型**：先 `lookup_doc` 学卡格式 + `find_example` 找相近样例；自举出的可跑样例存**自主学习库**，供以后复用。

## 查资料要节制（防空转）
- 同一主题的 `lookup_doc` / `find_example` **最多查 2~3 次**；查够就动手起草，
  **靠 `run_relap5` 的报错来定位问题**，而不是反复查文档。
- 连续多次同类查询会触发熔断（空转保护）——被拦时要改变策略，而不是继续查。

## 学新类型流程（自举 = 读手册“学会”，不是找结构）
> 手册是**说明书**，里面**没有现成卡结构**。学习 = **读懂文字** → **自己构建** → **真跑验证**。
1. `lookup_doc(类型)` 读该部件的手册**文字说明**，理解：它由哪些卡组成、每张卡有哪些字段、
   字段的含义/单位/顺序与规则（读 1~2 次就够，**不要反复翻找**）；
2. 依据**理解**自行构建**最小**可跑模型（`write_file`）——按规则写，不是找卡照抄；
3. `run_relap5`；
4. 报错 → `parse_output` 读错 → 对照手册**对应说明**想清楚为什么错 → 改 → 重跑；
5. 通过后 `save_example` 存入**自主学习库**，供以后复用。
